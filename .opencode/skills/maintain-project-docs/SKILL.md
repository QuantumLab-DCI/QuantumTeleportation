---
name: maintain-project-docs
description: "Maintain English README, docs, specs and proportional function documentation. Use when scope, architecture, execution, dependencies, examples, outputs or diagnosis change."
---

1. Identify documentation affected by the actual change and its canonical source.
   Reuse the team's visual README style without importing another project's stack,
   capabilities, version badges or URLs. Keep product docs and code in English.
2. Maintain a readable title/navigation, purpose, current scope, architecture,
   verified Qollab run instructions, output interpretation, limits and docs links.
   Mark missing application implementation accurately; do not fabricate run commands.
3. Keep requirements/tasks/evidence in the current spec, module decisions in the
   architecture doc, and working diagnostics/Git conventions in development docs.
   Add pages only when their audience or size warrants it; link rather than copy.
4. Keep source/result blocks aligned with the code actually executed. Label static
   outputs and pending team content. Preserve scientific sources and third-party
   attribution; document equivalent circuit representations accurately.
5. Use proportional docstrings/JSDoc and comments explaining reasons. Preserve
   requested English CSS section comments. Verify local links, assets and affected
   instructions where possible. Include docs with the same functional change and
   report instructions or learning outcomes that remain unverified.
